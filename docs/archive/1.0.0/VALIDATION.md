# Validation record

14 October 2026. Folio Scan 1.0.0, package `com.folio.scanner`, min SDK 26, target SDK 36.

## Build and package

- Universal debug build: passed.
- ARM64 debug build using `-PfolioAbi=arm64-v8a`: passed.
- `:app:lintDebug`: passed, **0 errors**. Remaining warnings concern pinned dependency updates, portrait orientation, drawing allocations, and localization/legacy API styling; the initial API-27 style error was corrected.
- Both delivered APKs pass Android `apksigner verify` and are signed with the Android development key.
- REA inspected the exact final universal APK. The [REA report](rea/README.md) records its digest, the Android manifest, processor inventory, and complete detector/enhancement methods. The ARM64 and universal APKs contain identical Java DEX payloads.

## Android runtime tests

An Android 14 / API 34 x86_64 emulator with a Pixel 6 display was installed and booted with KVM and software graphics. The tests execute Android's real bitmap/PDF APIs and the bundled OpenCV JNI implementation.

The full suite passed **12/12 tests** after the enhancement fix. After a final system-bar/inset styling change, the **3 UI/storage tests were repeated and passed**; processor code was unchanged. Raw output: [full suite](instrumentation-results.txt), [final UI repeat](ui-instrumentation-results.txt).

Coverage includes:

- Skewed page detection against expected corners, actual perspective crop, and removal of the surrounding desk.
- Uniform input rejection, invalid crossed corners, and tiny-image rejection.
- The app's actual sample photograph: page detection, retained teal hue/darkness, and panel uniformity.
- Paper-shadow brightening, retained red/blue ink and dark text.
- A broad colored panel: no new internal brightness gradient or surrounding paper halo.
- Original/grayscale/binary output behavior, output size bounds, and aspect ratio.
- EXIF orientation and a long receipt PDF with preserved geometry.
- Actual JPEG save/read, rename/list/delete, and PDF opening through Android PdfRenderer.
- Sample → crop → filters → save → rename → reopen, including Activity recreation in crop, preview, and saved states.

The first screenshot review revealed a halo around saturated artwork even though basic tests passed. The illumination estimator was changed to use neutral paper samples, and artwork adjustment was bounded. The sample teal pixel changed from RGB `(7,92,102)` to `(4,93,106)` after correction, compared with the earlier overly bright `(89,158,172)`. New regression tests and screen review passed.

Commands used for runtime testing:

## Native flow smoke checks

- Android's document picker imported the sample JPEG from Downloads; actual page detection led to the crop screen.
- The system PDF picker exported a readable, nonempty `%PDF-1.4` file (753,633 bytes). Android's “Don't keep activities” setting was enabled for that check; the saved scan restored and export completed after returning from the picker. The setting was then reset.
- CameraX showed the emulator camera, captured a real JPEG (60,938 bytes), and entered crop editing. The emulator scene contains no paper; the app correctly offered manual corners when no page was detected.
- Android crash logs were empty during these checks.

Real phone camera behavior, automatic capture stability, glare, curled pages, faint boundaries, and varied lighting still need customer photographs and physical-device testing.
