# Folio Scan for Android

Folio Scan 1.1.0 detects a paper document, corrects its perspective, and automatically cleans up its **existing colors**. Camera capture and photo import share a Java adaptation of [OpenScan's document detector](docs/OPENSCAN_DETECTION.md). OpenCV performs the perspective correction and color enhancement offline.

## Try it

Install a debug APK on Android 8.0 or newer:

- [ARM64 APK](deliverables/folio-scan-arm64-debug.apk): 29.4 MB, for modern ARM64 phones.
- [Universal APK](deliverables/folio-scan-universal-debug.apk): 146.2 MB, includes ARM32, ARM64, x86, and x86_64.
- [Source ZIP](deliverables/folio-scan-source.zip).

These are test builds signed with the development key. `adb install -r` updates an existing Folio installation while retaining its saved scans.

1. Choose **Scan with camera** or **Import photo**. **Try a sample page** runs a generated photograph through the actual detector.
2. Check the detected corners. Drag them if needed; **Reset edges** selects the photograph bounds and **Rotate** turns the image clockwise.
3. Tap **Apply scan**. **Auto color** is selected automatically. Compare **Original**, **Gray**, and **B&W**.
4. **Save scan**, then export a JPG/PDF or share a PDF. Rename and delete are available on saved scans.

Automatic camera capture requires at least three fresh detections stable for 700 ms. Elapsed time can be longer when frames take longer to process. Manual capture remains available, and permission denial leaves photo import available.

Scans are kept in private app storage. Export copies with the Android file picker before uninstalling the app. Processing uses no server; the app requests no internet or broad storage permission. Exported copies are stored wherever the user chooses.

## Build

Open this folder in Android Studio, or use JDK 17, Android SDK platform 36, and the checked-in Gradle wrapper:

```sh
export JAVA_HOME=/path/to/jdk-17
./gradlew :app:assembleDebug
./gradlew :app:assembleDebug -PfolioAbi=arm64-v8a
```

On the development workstation the JDK is `/home/sanket/.jdk/current` and SDK is `/home/sanket/Android/Sdk`. Set your own `sdk.dir` in `local.properties` or use `ANDROID_HOME`. Build output is `app/build/outputs/apk/debug/app-debug.apk`; each ABI build replaces that output, so copy it before building another variant.

```sh
./gradlew :app:lintDebug
./gradlew :app:connectedDebugAndroidTest
adb install -r app/build/outputs/apk/debug/app-debug.apk
```

Connected tests require a device/emulator supported by the built APK. They execute Android's bitmap/PDF APIs and real OpenCV JNI. The detector also has expected coordinates independently generated by the original OpenScan Dart functions; see the [detector notes](docs/OPENSCAN_DETECTION.md) for reproduction.

## Main code

- `MainActivity.java`: capture/import, crop/preview flow, lifecycle restoration, library, export, and sharing.
- `processing/OpenScanDetector.java`: OpenScan's grayscale, multi-threshold edge, component, hull, and quadrilateral-consensus detector.
- `processing/DocumentProcessor.java`: detector entry point, four-point perspective warp, lighting normalization, and color filters.
- `ui/LivePageTracker.java`: corner correspondence, smoothing, confirmed page changes, and fresh-frame capture stability.
- `ui/PreviewFrameMapper.java`: excludes camera-preview letterboxing from detection and maps corners back to the overlay.
- `ui/CropImageView.java`: normalized, constrained, draggable document corners.
- `storage/ScanStore.java`: private JPEG library, single-page PDF export, and bounded EXIF-aware photo decoding.
- `ui/ScanIllustration.java`: original vector illustration and synthetic sample photograph.

Detection uses a maximum edge of 700 pixels; perspective-corrected output is capped at 2600 pixels. When no quadrilateral is found, manual crop remains available. Auto color estimates page lighting and conservatively corrects paper color in Lab space while retaining colored ink. The detector's quality value describes area and corner geometry; it is not an accuracy probability.

## OpenScan, REA, and OKEN

The detector is adapted from OpenScan commit `27bb7ab973fbb621fce182c43bc875856c785a30`. Its [BSD 3-Clause license](licenses/OpenScan-BSD-3-Clause.txt) is included in the source and app assets, and is accessible through **About → Third-party notices**. [Adaptation and validation details](docs/OPENSCAN_DETECTION.md) describe the source files and Android integration.

The supplied [REA project](https://github.com/morluto/rea) provides reverse-engineering tools. REA was used to inspect Folio's built APK; commands and evidence are in [docs/REA_FINDINGS.md](docs/REA_FINDINGS.md). No OKEN APK was supplied, so exact OKEN behavior was not compared.

## Practical limits

The detector is intended for flat, rectangular pages. Clutter, clipped pages, glare, and curved books may need manual correction. Enhancement cannot restore detail lost to blur or blown-out highlights, and broad colored artwork may become lighter. Synthetic regression fixtures cover several previously missed page shapes, but customer photographs and a physical Android phone are still needed for customer acceptance. This version exports one page per scan.
