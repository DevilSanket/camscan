## Android runtime tests

An Android 14 / API 34 x86_64 emulator with a Pixel 6 display ran the tests using Android's bitmap/PDF APIs and bundled OpenCV JNI.

The full suite passed **27/27 tests** in 20.008 seconds. A subsequent targeted `OpenScanParityTest` run passed **3/3 tests** in 1.743 seconds after adding the before/after regression test. Two tests overlap between runs, giving **28 distinct passing tests**; a single full 28-test run is not claimed. Raw output: [full suite](instrumentation-results.txt), [targeted detector checks](openscan-parity-results.txt).

Coverage includes:

- Nine synthetic grayscale fixtures compared against coordinates generated by the original OpenScan Dart functions, with `1e-6` pixel-coordinate tolerance.
- Android bitmap-to-normalized-coordinate adaptation on the same detected pages; uniform white and dark inputs rejected.
- Four reproduced misses in the original Folio detector: faint page, small page, narrow receipt, and near-frame page. The new detector finds all four.
- Previous raw corners favoring the matching document when more than one candidate is present.
- Camera overlay jitter, corner relabeling, confirmed page jumps, brief dropout display, slow drift, auto-capture toggling, capture cooldown, and fresh-frame stability.
- Camera preview mapping with portrait/landscape bars, rotated or mirrored transforms, view clipping, rounding, and missing/tiny content rejection.
- Perspective crop, crossed-corner rejection, tiny-input rejection, output bounds, and aspect ratio.
- Sample-page detection and color retention; shadow brightening; retained red/blue ink and dark text; broad colored panels without a new brightness gradient or paper halo.
- Original/grayscale/binary filters, EXIF orientation, and receipt PDF geometry.
- JPEG save/read, rename/list/delete, PDF opening through Android PdfRenderer, and sample → crop → filters → save → reopen flows with Activity recreation.

The perspective-warp and color-enhancement code was unchanged for this release; its existing runtime regression checks pass with the new detector.

## Native flow smoke checks

The installed universal 1.1.0 APK passed additional camera and import smoke checks on the API 34 emulator. CameraX streamed the emulator's virtual room, the new detector drew a changing overlay inside the preview content, and enabling automatic capture produced a JPEG and opened the detected-corner crop screen. This checks the camera integration and capture flow; the room contains rectangular structures, so it does not measure document recognition accuracy.

Android's system document picker imported the generated `folio-sample.jpg`. The app found its page, opened the crop screen, and **Apply scan** produced the Auto color review. The camera/import crash buffer was empty. [Smoke record](native-flow-smoke.txt) and [crash buffer](camera-import-crash-log.txt) preserve these checks.

The archived 1.0.0 record documents Android picker import, PDF export with Activity destruction, CameraX JPEG capture, and empty crash logs. Those checks remain historical evidence for the earlier build. The current full suite verifies sample processing, storage, and export APIs, but not every physical-camera or system-picker interaction.

## Review artifacts and limits

Version 1.1.0 artifacts include [sample detection](screenshots/crop-1.1.png), [Auto color](screenshots/auto-color-1.1.png), [picker import crop](screenshots/import-crop-1.1.png), [picker import Auto color](screenshots/import-auto-color-1.1.png), [camera overlay](screenshots/camera-1.1.png), and [camera capture result](screenshots/camera-capture-1.1.png). The camera pictures show a virtual room, not a physical document.

The unsuffixed screenshots and [enhanced JPEG](screenshots/scan-result.jpg) are historical 1.0.0 artifacts. [Sample photograph](screenshots/sample-photo.jpg) is the generated input reused for the current picker check.

Synthetic pages establish the covered regressions and agreement with OpenScan on those fixtures. They do not establish accuracy on all customer documents. Like the upstream contour detector, this implementation can select other rectangular objects in a scene; the virtual-room smoke check illustrated that limitation. Customer photos and a physical phone are still needed to assess glare, curled pages, clutter, faint boundaries, varied lighting, and camera movement. No OKEN APK was available, so exact OKEN output matching was not tested. These are development builds for review, not store releases.
